# CI setup — GitHub Actions for DiagForge

The repository ships one CI workflow:
[`/.github/workflows/diagforge-pr.yml`](../.github/workflows/diagforge-pr.yml).
It runs `diagforge analyze` on every example directory touched by a pull
request and posts the top hypothesis + matched mitigation patterns as a PR
comment, so a reviewer can see the diagnostic verdict without checking out
the branch and running the tool locally.

## One-time setup

1. **Add `ANTHROPIC_API_KEY` to repository secrets**.
   GitHub → repo Settings → *Secrets and variables* → *Actions* →
   *New repository secret*.
   Name: `ANTHROPIC_API_KEY`. Value: your Anthropic key (`sk-...`).
2. **Grant the workflow permission to comment on PRs.**
   Already declared in the workflow as
   `permissions: pull-requests: write`. No further action needed for
   public repos.

   For repos under an organization with stricter defaults, also visit
   *Settings* → *Actions* → *General* → *Workflow permissions* and ensure
   "Read and write permissions" is allowed (or grant it per-workflow).

That's the entire setup. The action triggers automatically on the next PR
that modifies anything under `examples/` or `traces/`.

## How it decides what to analyse

The workflow uses `git diff` against the PR's base ref to enumerate
directories under `examples/` or `traces/` that have *any* added or
modified file. For each such directory it looks for:

* a trace file matching `*.asc` or `*.log` (first match wins),
* `dtcs.json` (required),
* an optional `*.dbc`.

Directories that don't satisfy the minimum trace+dtcs requirement are
skipped with a `::notice::` log line and the rest of the run proceeds.

## What gets posted on the PR

A single comment per workflow run, generated by
`.github/scripts/summarize_reports.py`, structured as:

```
## DiagForge PR analysis

### `p0300_intermittent_misfire`
_Trace `trace.asc` · 94 frames · 960 ms duration_

**P0300** _(obd2)_ Random/Multiple Cylinder Misfire Detected
- 🔴 Top hypothesis (high): Insufficient misfire dematuration timer
  - Evidence: `engine_rpm dropped 4 time(s)...`
- 🛠 Mitigation: `dematuration_timer` — Dematuration / fault-clear timer
  (`dematuration_time_ms=1500`)
```

A `diagforge-pr-reports` artefact is also uploaded with the full
`report.json`, `report.html`, and `manifest.json` for each analysed
example, retained for 14 days.

## Performance

* The poetry venv is cached, keyed on `poetry.lock`. Cold install: ~90 s
  (dominated by `pyarrow` for streamlit). Cached: ~5 s.
* DiagForge analysis: ~3-5 s per example, dominated by the Anthropic
  round trip. The action limits itself to changed directories so a
  no-op PR is a no-op run.
* Total wall time for a PR adding one example: typically under 2 minutes.

## Caveats and trade-offs

* **Trace data is sent to Anthropic.** Don't commit traces you wouldn't
  share with a third party. For OEM-confidential captures, run the tool
  locally; the action is for the public demo cases.
* **API spend per PR is modest** but non-zero. For high-traffic public
  repos, consider gating the workflow behind a label or restricting to
  members of the org with a `pull_request_target` + branch protection
  combo.
* The action **does not** run the unit tests — those have their own CI
  workflow (out of scope for this PR; add `.github/workflows/test.yml`
  separately if/when desired).

## Local rehearsal

The `summarize_reports.py` script is standalone — to preview a comment
locally:

```bash
poetry run diagforge analyze examples/p0300_intermittent_misfire/trace.asc \
    --dtcs examples/p0300_intermittent_misfire/dtcs.json \
    --dbc  examples/p0300_intermittent_misfire/engine.dbc \
    --output /tmp/pr-rehearsal/p0300/
python .github/scripts/summarize_reports.py /tmp/pr-rehearsal/p0300/report.json
```
